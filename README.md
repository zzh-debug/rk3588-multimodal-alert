## 1. 最终目标态项目描述

以下内容是固定终极目标，不是当前完成声明。所有性能、精度和可靠性结论必须
由真实板端数据替换，不能用 SDK 中存在对应库来代替项目实现。

**项目二：基于 RK3588 的可见光-热成像协同感知与低照度预警系统**

个人独立开发｜ATK-DLRK3588｜RK3588 异构计算平台

技术栈：C/C++、V4L2、DMA-BUF、RGA、RKNN、MPP、RTSP、OpenCV、多线程

- 并行采集 RKISP 输出的 IMX415 NV12 可见光帧和 MLX90640 32x24 成对原始热阵列帧，统一采用 `CLOCK_MONOTONIC` 时间基准，通过有界时间队列实现最近邻帧匹配、超窗丢弃及配对延迟统计，解决两类传感器帧率和采集周期不一致的问题。
- 在用户空间完成 MLX90640 EEPROM 参数解析、温度矩阵计算、发射率补偿、坏点修复、时域滤波和伪彩热图生成；在固定安装和限定距离条件下建立热成像至可见光画面的区域映射，实现热目标与人员检测框的 ROI 级匹配。
- 使用 RGA 对 4K 可见光画面进行裁剪、等比例缩放和颜色转换，生成 640x640 模型输入；通过 RKNN 在 NPU 部署人员检测模型，并将视觉检测结果与人体热源区域进行规则融合，实现弱光场景下视觉目标与人体热源的二次确认。
- 构建基于 DMA-BUF、多缓冲池和有界队列的多线程流水线，显式管理 V4L2、RGA、RKNN 与 MPP 之间的 fd、stride、缓存同步和 Buffer 生命周期，实现采集、预处理、推理、融合与编码解耦，减少可见光主路径中的 CPU 全帧复制。
- 设计带滞回和冷却时间的低照度补光状态机，综合画面亮度与持续热目标动态控制白光 LED 的 PWM 占空比；在编码前叠加人员框、区域温度与告警状态 OSD，使用 MPP 完成 H.264 硬件编码并接入 RTSP 服务推流。

## 3. 第一版边界和顺序

```text
项目一稳定采集 ABI + AIQ/IQ + PWM LED（已通过）
  -> P2.1 双路采集、时间戳定义和最近邻匹配（首版已实现，扩展门禁进行中）
  -> P2.2 用户态温度算法和固定距离区域映射
  -> P2.3 RGA 640x640 预处理、单一人员模型和规则融合
  -> P2.4 DMA-BUF 多池与有界流水线
  -> P2.5 H.264、单路 RTSP 和小区域 OSD
  -> P2.6 经硬件验收的 PWM 补光状态机
```

第一版不承诺像素级对齐、4K tensor 推理、端到端零拷贝、复杂跟踪、H.265
双编码或内核无感恢复。完整版是否加入这些能力，只依据实测收益和风险另行立项。

## 4. 证据规则

- 每个运行结果关联应用 commit、Image/DTB/module hash、IQ/模型/标定文件 hash 和命令。
- 时间匹配报告必须定义可见光 SOF 与热阵列两个 subpage 时间戳的语义。
- 区域映射必须写明 MLX90640 FOV 型号、机械基线、适用距离和 P50/P95 误差。
- DMA-BUF 只以 fd/ownership/cache/fence 和 profile 证据证明减少 CPU 拷贝。
- RTSP/OSD/编码只有在本项目应用真正接入并通过板测后才能写成完成项。
