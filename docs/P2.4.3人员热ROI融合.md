# P2.4.3 人员框与粗粒度热ROI融合

## 1. 阶段结论

P2.4.3已完成实时人员框×热ROI规则融合、双路结果级时间匹配、告警去抖和板端门禁。
实现提交为`d9507a8f5572`，瞬态非有限热像素修复提交为`2b1a59cb6dc3`。

本阶段使用首轮1 m临时标定，只承诺固定安装、1 m附近的区域级关联。标定拟合最大
误差146.693 px、独立验证最大误差约232 px，因此运行时明确使用240 px保守扩张，
不把结果称为像素级对齐或正式标定精度。

## 2. 实时数据流

```text
IMX415 V4L2 MMAP/EXPBUF
  -> 容量1 drop-oldest租约队列
  -> RGA直写RKNN non-cacheable io_mem
  -> YOLOv5 person框（原始3840x2160坐标）
                         \
                          -> 有界结果级最近邻Join -> Fusion -> AlertEvent
                         /
MLX90640 ZMLX pair
  -> EEPROM温度数学/坏点修复/时间感知EMA
  -> 32x24温度矩阵与热连通域
```

时间Join复用P2.1的单调时间戳语义，默认等待20 ms可见光lookahead，并在50 ms门限内
选取最近可见光结果。Join只持有轻量人员框和32×24温度矩阵，不延长4K V4L2 Buffer
生命周期；可见结果上限96、热结果上限24，输出队列容量8，所有边界均有统计。
`FrameSynchronizer::drain_matches()`在消费后清空匹配记录，避免长期运行累积。

## 3. 融合规则

| 项目 | 默认值 | 语义 |
|---|---:|---|
| 热背景 | 有限像素中位数 | 降低单个热物体和离群点对背景估计的影响 |
| 热激活阈值 | `max(30℃, 背景+4℃)` | 当前只作相对热证据，不声明绝对测温精度 |
| 最小热连通域 | 2像素、8邻域 | 剔除孤立单像素噪声 |
| 映射不确定性 | 240 px | 覆盖首轮独立验证约232 px最大误差，裁剪到4K边界 |
| 热区覆盖率 | 人员框与扩张热AABB交集/扩张热AABB面积，至少0.10 | 保守的区域级近似，不做像素级轮廓匹配 |
| 人员置信度 | 0.25 | 与P2.3验收模型门限一致 |
| 激活去抖 | 连续2个融合帧 | 抑制单帧偶发重叠 |
| 释放去抖 | 连续3个未命中帧 | 避免热区边缘抖动导致闪断 |
| 冷却时间 | 1000 ms | 释放后抑制立即重复激活 |

每个CSV事件记录可见/热序号、带符号时间差、人员数、热区数、匹配数、背景温度、
激活阈值、匹配最高温、告警状态和状态迁移。系统只在同一时间对内同时存在合格
人员框和合格热区覆盖时产生融合证据。

## 4. 瞬态非有限像素

首轮30秒正式运行在第82个有效热pair观察到`temperature=767/768`，旧行为把整条
实时链路作为致命错误退出。采集payload、时间戳和NPU路径均无错误，问题是官方
声明坏点修复后仍偶发留下一个非有限温度像素。

修复保持严格上限：只有启用坏点修复且非有限像素不超过4个时，才用原始有限邻域
的中位数补洞；先在半径1查找，必要时扩大到半径2。超出4个或找不到有限邻居仍
立即失败。结果分别统计温度和强度修复数量，不静默吞掉大面积异常。纯函数测试覆盖
超限拒绝、失败不部分改写和2像素修复；修复后30秒预跑处理229个热帧并实际记录
1个温度像素修复，0数学失败。

## 6. 事实边界与下一步

- 当前结果证明实时链路、时间Join、规则执行和状态机工作，不等于多人身份跟踪；
- 默认现场运行中的人员框/热区数量受当时画面影响，不能替代新的融合人工标注集；
- 没有参考温度计/黑体，30℃阈值只是工程规则，不声明绝对温度误差；
- 临时标定只适用于固定姿态和1 m附近，明显改变距离、支架或镜头后需重新验证；
- P2.5接入MPP H.264、小区域OSD和MediaMTX RTSP，告警事件直接作为OSD输入。
