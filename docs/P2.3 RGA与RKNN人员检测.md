# P2.3 RGA与RKNN人员检测

> 实现基线：`80346d92fc3ad4be337ff038025ca9200d7fd5fb`<br>
> 真机日期：2026-08-28（Asia/Shanghai）<br>
> 当前结论：P2.3.1功能/性能基线通过，P2.3仍缺真实场景标注集评估

## 1. 当前实现

| 环节 | 当前实现 |
|---|---|
| 输入 | 通过media graph动态定位`rkisp_mainpath`，采集3840×2160单平面NV12 MMAP帧 |
| 安装方向 | 与已验收Qt查看工具一致，先把竖装IMX415原始帧顺时针旋转90°；CLI仍支持0/180/270配置 |
| RGA | 一次`improcess`完成旋转、NV12到RGB、等比例缩放，并写入预填114的640×640 letterbox区域 |
| 坐标 | 保存原始尺寸、旋转后尺寸、实际整数缩放和padding；检测框先去padding/缩放，再逆旋转回原始4K坐标 |
| RKNN | 使用SDK自带RK3588 YOLOv5s 640模型，应用以NHWC UINT8 RGB提交，Runtime按模型INT8输入契约量化 |
| 后处理 | 解码stride 8/16/32三个INT8 affine输出，只计算COCO class 0 person，做person-only NMS，默认置信度0.25、IoU 0.45 |
| 工具 | `p2_person_detect`跑真实相机并输出延迟JSON/检测CSV；`p2_person_detect_nv12`跑确定性NV12样本 |

模型二进制不进入仓库。SDK路径、大小、SHA-256、来源、许可证、输入输出布局和
量化方式以`models/yolov5s_rk3588_640.manifest`为准。SDK README指向Rockchip
官方`rknn_model_zoo`；该源仓库声明Apache-2.0。私有仓库未来公开前仍需重新
核查模型权重和上游YOLO实现的可分发边界。

## 2. 坐标契约

以当前3840×2160竖装传感器、顺时针90°为例：

| 量 | 值 |
|---|---:|
| 原始坐标范围 | x=`[0,3840]`，y=`[0,2160]` |
| 旋转后尺寸 | 2160×3840 |
| letterbox有效图像 | 360×640 |
| padding | left=140，top=0，right=140，bottom=0 |

模型框反算顺序固定为“去padding -> 分别除以实际`scale_x/scale_y` -> 逆旋转 ->
钳位到原始4K边界”。原生单测覆盖0°和90°的整幅反算、非法旋转和零尺寸拒绝；
YOLO合成测试覆盖量化解码、anchor数学、person-only NMS和小张量拒绝。

## 3. 真机结果

### 3.1 固定功能样本

SDK `bus.jpg`在板端由FFmpeg转换为640×640 NV12，输入
`p2_person_detect_nv12`。程序使用真实RGA、RKNN Runtime和NPU，检出4个人，
置信度约0.880、0.871、0.828和0.300；单次总耗时22.756 ms。这个样本证明
真实模型输出能被本项目后处理正确消费，但不是精度数据集，不能据此声明mAP。

### 3.2 4K实时性能

| 指标 | 结果 |
|---|---:|
| 应用提交 | `80346d92fc3a` |
| RKNN API / 驱动 | `2.0.0b0` / `0.9.6` |
| 计时帧 | 831（另有10帧warm-up） |
| 实际吞吐 | 28.187 FPS |
| RGA P50 / P95 / P99 / max | 10.797 / 14.607 / 15.703 / 17.259 ms |
| RKNN P50 / P95 / P99 / max | 21.370 / 24.934 / 26.407 / 32.695 ms |
| 总耗时P50 / P95 / P99 / max | 34.185 / 39.648 / 41.616 / 46.827 ms |
| 坏bytesused / 非单调时间戳 | 0 / 0 |
| 可见光sequence gap | 49 |
| 当前场景人员 | 0（镜头前为空场景） |

该结果达到实施计划中“暂定不低于15 FPS且P95低于50 ms”的性能门槛。49次
sequence gap来自首版在V4L2回调里同步执行约34 ms推理；它被明确记录，留给
P2.4的采集/推理解耦、有界队列和Buffer池治理，不能写成零丢帧或最终流水线。
