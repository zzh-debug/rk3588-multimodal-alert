# P2.4.1/P2.4.2a 采集推理解耦与DMA-BUF源路径

## 1. 本阶段结论

P2.4.1 已把可见光采集与 RGA/RKNN 人员推理从同一个同步回调拆为两个执行域。
4K NV12 帧通过 V4L2 MMAP Buffer 租约进入有界 drop-oldest 队列，不做应用层
4K 全帧复制；推理完成、队列淘汰旧帧或退出清空队列时，租约析构并把对应 Buffer
归还驱动。

60 秒板端门禁中，采集 1796 帧，采集侧 `sequence_gaps=0`、坏 payload 为 0、
缺失单调时间戳为 0。推理略慢于 30 FPS 时，有 120 帧被明确归类为队列主动淘汰，
而不是采集漏帧。P2.4.1 可以关闭。

P2.4.2a 随后完成 `VIDIOC_EXPBUF` 和 RGA `importbuffer_fd`：6 个 V4L2 Buffer
各导出一个 DMA-BUF fd，RGA 只为每个 fd 建立一次缓存 handle。正式 60 秒达到
30.019 推理 FPS、0 采集 gap、0 队列淘汰，端到端 P95 降至 36.131 ms。

这仍不是 P2.4 全部完成：640×640 RGB 目标目前注册为 RGA virtual-address handle，
随后仍通过 `rknn_inputs_set` 进入模型；RKNN `io_mem`、明确 cache/fence 日志及后续
MPP 多池尚未完成，因此不得称为端到端零拷贝。

## 2. 为什么需要解耦

P2.3 的 `p2_person_detect` 在 V4L2 采集回调中串行执行 RGA、RKNN 和后处理。
30 秒旧基线出现 49 次可见光序号跳变，说明驱动在应用持有 Buffer 做推理期间已经
丢失采集机会。P2.4.1 的目标不是让 NPU 突然变快，而是让采集持续按相机节奏运行，
并把算力不足造成的淘汰变成有边界、可统计的正常策略。

## 3. Buffer ownership

```text
V4L2 queued Buffer
  -> capture线程 DQBUF
  -> VisibleFrameLease（唯一可移动owner）
  -> capacity=1 的 BoundedLatestQueue
       -> 满队列：析构最旧租约 -> QBUF
       -> 正常取帧：推理线程持有租约
  -> RGA/RKNN完成 -> 析构租约 -> QBUF
  -> 停止：清空pending租约 -> QBUF -> STREAMOFF/unmap/close
```

`VisibleCaptureSession` 由采集循环和所有未归还租约共同持有。最后一个租约释放前，
fd 和 mmap 地址不会失效；所有 `VIDIOC_DQBUF`/`VIDIOC_QBUF`/STREAM ioctls 由互斥锁
串行化。原有同步 `run_frames()` 继续使用同一租约实现，但回调返回即归还 Buffer，
因此没有保留悬空指针。

## 4. 队列策略

| 项目 | 当前值 | 说明 |
|---|---:|---|
| V4L2 Buffer 数 | 6 | 驱动、采集、队列和推理共享生命周期 |
| 默认队列容量 | 1 | 始终优先处理最新帧，降低告警陈旧度 |
| 满队列策略 | drop-oldest | 淘汰旧租约并立即 QBUF，不阻塞采集线程 |
| 关闭策略 | discard pending | 分类记录 `shutdown_drops`，清空后唤醒消费者 |
| 4K CPU 全帧复制 | 0 | 仅指采集到推理交接；不代表端到端零拷贝 |

15 秒对照表明容量 1 更适合实时预警：

| 队列容量 | 采集 FPS | 采集 gap | 主动淘汰 | 端到端 P50 | 端到端 P95 |
|---:|---:|---:|---:|---:|---:|
| 1 | 29.562 | 0 | 18 | 47.081 ms | 66.219 ms |
| 3 | 29.537 | 0 | 6 | 111.016 ms | 129.410 ms |

容量 3 会少淘汰一些帧，但这些帧到达算法时已经更旧，所以默认冻结为容量 1。

## 7. P2.4.2a DMA-BUF源路径

实现提交：`1ed71fd650db52c3240389f5b98c2e0c88b2478b`

```text
V4L2 MMAP Buffer（session拥有）
  -> VIDIOC_EXPBUF（每个Buffer一个fd，session关闭）
  -> RGA importbuffer_fd（每个fd一个缓存handle，detector释放）
  -> RGA NV12旋转/letterbox
  -> 640x640 RGB virtual-address handle
  -> rknn_inputs_set（当前仍有模型输入复制边界）
```

同一帧连续 5 次分别走 DMA-BUF 和 MMAP 路径，人员框数量、坐标和置信度完全一致，
`checks=5`、`mismatches=0`。同代码15秒A/B与正式门禁如下：

| 路径 | 采集gap | 主动淘汰 | 推理FPS | RGA P50 | 端到端P50/P95 |
|---|---:|---:|---:|---:|---:|
| MMAP A/B 15秒 | 0 | 35 | 27.669 | 11.588 ms | 51.171/67.825 ms |
| DMA-BUF A/B 15秒 | 0 | 0 | 30.033 | 7.041 ms | 34.165/44.362 ms |
| DMA-BUF正式60秒 | 0 | 0 | 30.019 | 6.957 ms | 29.957/36.131 ms |

正式60秒还得到：6/6 Buffer成功EXPBUF、RGA fd import恰好6次、1796 DQBUF、
0坏payload、0缺失单调时间戳、退出后pending为0。程序SHA-256为
`9d3a5ec5da59c0a66b47f646c3c179f8547028b605e292974715f155d85404d3`。
