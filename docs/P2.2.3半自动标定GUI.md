# P2.2.3 半自动跨光谱标定GUI

> 建立日期：2026-08-29（Asia/Shanghai）<br>
> 当前状态：原生核心测试与AArch64交叉编译通过；板端Wayland交互、真实暖靶拟合
> 和独立验证尚未执行

## 1. 目的和边界

`p2_calibration_gui`复用`qt_test_camera`已经验证的竖屏双路布局，但正式接入
项目二的动态设备发现、V4L2采集、MLX90640温度数学、时间感知滤波、热目标质量
门禁和单应拟合。用户只需把静态暖目标移动到黄色十字；程序把十字换算到原始
3840×2160坐标，并自动从32×24温度矩阵提取对应热质心。

本工具只生成固定安装、限定距离、区域级映射，不做以下声明：

- 不标定MLX90640绝对测温精度；
- 不承诺不同深度目标的像素级配准；
- 不把Qt预览的肉眼同步替代P2.1时间基线；
- 未完成独立验证时不把配置作为正式业务成果。

## 2. 当前安装与显示坐标

两个模组当前固定在同一支架上，镜头中心有机械基线，光轴近似平行同向。屏幕按
手机竖屏看时是上下两个横画面；用户按开发板实际摆放观察时是左右两个竖画面。
当前经过实物运动核对的显示默认值为：

| 路径 | 默认显示变换 |
|---|---|
| IMX415 | rotation=0，水平翻转=false，竖屏源坐标垂直翻转=true |
| MLX90640 | 顺时针90°，不翻转 |

这些参数只负责原始坐标与显示坐标互换。标定CSV和最终单应矩阵始终使用原始
32×24热坐标和原始3840×2160可见光坐标，不使用LCD缩放后的坐标。

## 3. 自动门禁

| 项目 | 默认值 | 作用 |
|---|---:|---|
| 背景帧 | 16 | 暖目标移走后计算逐像素背景均值 |
| 前景温差 | 2.5℃ | 高温核心阈值的最低下限 |
| 峰值温差 | 6.0℃ | 拒绝不明显的暖目标 |
| 高温核心阈值 | 峰值温差的60% | 身体等大面积低温差区域不参与质心 |
| 高温核心像素 | 2～96 | 单像素目标提示尺寸过小或距离过远 |
| 第二热区峰值比 | 不高于0.85 | 拒绝同时出现两个温度接近的热目标 |
| 峰值到质心距离 | 不高于2热像素 | 白圈远离最热点时拒绝采集 |
| 每点稳定帧 | 4 | 使用温差权重平均热质心 |
| 最大质心漂移 | 0.75热像素 | 目标移动时自动重新采样 |
| 可见/热时间差 | 不高于100 ms | 静态靶首个后继可见光帧门禁 |
| 热处理连续失败 | 8帧 | 单帧异常只丢弃并自动恢复，连续失败才停机 |
| 拟合点/验证点 | 9/4 | 验证点完全不参与拟合 |

保存时还必须填写近端、标定和远端距离，并明确设置可接受的可见光像素误差门限。
默认显示120 px只是首轮区域级调试值，不是已经验收的项目指标；正式门限必须由
真实样本分布和人员框融合容差冻结。

## 4. 构建

在RK3588 Dev Container内以`vscode`用户执行：

```bash
cd /rk3588_dev/projects/rk3588_multimodal_alert
cmake -S . -B build/aarch64 \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/buildroot-aarch64.cmake \
  -DCAMERA_BSP_ROOT=../rk3588_camera_bsp \
  -DP2_BUILD_HARDWARE=ON \
  -DP2_BUILD_CALIBRATION_GUI=ON \
  -DBUILD_TESTING=OFF
cmake --build build/aarch64 --target p2_calibration_gui --parallel
file build/aarch64/p2_calibration_gui
```

完整分项构建脚本`scripts/build_aarch64.sh`也包含该目标。

## 5. 部署和运行

部署会写入NFS根文件系统，执行前须按项目远程指南重新确认开发板根挂载。容器内：

```bash
sudo install -m 0755 build/aarch64/p2_calibration_gui \
  /rk3588_dev/nfs_rootfs/atk_dlrk3588/usr/bin/p2_calibration_gui
```

板端Wayland运行：

```bash
export XDG_RUNTIME_DIR=/run
export QT_QPA_PLATFORM=wayland
p2_calibration_gui
```

程序默认动态发现RKISP mainpath和ZMLX节点，不依赖`/dev/video45`或
`/dev/video0`。显示方向仍不正确时，可显式传入：

```bash
p2_calibration_gui \
  --visible-rotation 0 --visible-flip-h 0 --visible-flip-v 1 \
  --thermal-rotation 90 --thermal-flip-h 0 --thermal-flip-v 0
```

## 6. 触屏操作

1. 移走暖目标，点击“采集背景”，等待背景进度完成；
2. 在距离栏填写实际验证近端、当前标定距离和验证远端；
3. 黄色十字出现后，把小型静态暖目标中心移动到十字；
4. 确认红外画面的紫色短十字落在最高温核心、白圈包围该核心；只有门禁通过时
   “采集当前点”才可点击；
5. 点击“采集当前点”，保持不动直至4个稳定帧完成；
6. 依次完成3×3分布的9个拟合点；
7. 继续完成位于拟合网格内部的4个独立验证点；
8. 查看拟合最大误差、验证P95和最大误差；
9. 误差不超过界面门限后点击“保存配置”。

目标建议使用装热水的小瓶或边界清楚的小型平面暖靶。手掌和大杯子轮廓变化较大，
不适合作为正式点靶。背景采集期间必须移走目标，场景内也不要同时存在强度接近的
第二热源。

## 7. 输出

默认目录为`/tmp/p2-calibration-gui`，可用`--output DIR`修改：

| 文件 | 内容 |
|---|---|
| `gui-YYYYMMDD-HHMMSS.conf` | 可由业务加载的版本化3×3单应配置 |
| `correspondences.csv` | 9个拟合点和4个独立验证点的原始坐标 |
| `calibration-report.json` | 提交、型号、显示变换、距离、拟合及验证误差 |

保存动作只在拟合和独立验证完成、距离合法且拟合/验证最大误差不超过界面门限时
成功。输出位于`/tmp`，重启会丢失；正式验收时应把选定配置、报告和对应点复制
到仓库`calibration/`及对应证据目录，并记录文件SHA-256。
