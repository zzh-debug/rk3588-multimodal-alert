## 1. 本阶段范围

P2.1 只建立项目二的用户态采集和时间基础设施：

- 动态发现连接 IMX415 的 RKISP mainpath；
- 动态发现 `zzh_mlx90640` 的 `ZMLX` Meta 节点；
- 使用 V4L2 MMAP/poll 完成可见光 NV12 和热成像 Meta 并行采集；
- 统一使用 `CLOCK_MONOTONIC`，实现热完整帧与可见光帧的最近邻匹配；
- 用有界历史队列、超窗统计和可停止线程保证退出时回收 fd、mmap 和 V4L2 Buffer；
- 输出逐匹配 CSV 以及包含分位值和丢弃计数的 JSON 摘要。

本阶段不做温度计算、跨光谱标定、RGA、RKNN、LED自动控制、OSD、编码或RTSP。

## 2. 时间语义

| 数据 | 使用的事件时间 |
|---|---|
| 可见光 | V4L2 Buffer 的 `timestamp`，要求 `V4L2_BUF_FLAG_TIMESTAMP_MONOTONIC` |
| 热完整帧 | 两个 ZMLX Subpage `ready_timestamp_ns` 的中点 |
| 热帧跨度 | `second_ready_ns - first_ready_ns`，逐匹配记录 |
| 应用到达 | DQBUF 后调用 `clock_gettime(CLOCK_MONOTONIC)`，只用于调度延迟统计 |

热帧以时间中点进入匹配队列。同步器等待可见光时间轴至少超过热时间点
`lookahead`（默认20 ms）后再决策，从有界历史中选择绝对时间差最小的可见光帧。
默认最大匹配误差窗为50 ms；超过窗口只计数为 `unmatched_skew`，不生成假匹配。

## 3. 设备发现和格式门禁

可见光遍历 `/dev/media*`，在同一媒体图中同时寻找 `rkisp_mainpath` 与
`rkcif-mipi-lvds2`/IMX415，再由媒体实体的设备号映射到实际 `/dev/video*`。
采集协商固定为单 plane `V4L2_PIX_FMT_NV12`，运行时记录 width、height、
bytesperline、sizeimage 和 Buffer 数量。

热成像遍历 `/dev/video*`，同时检查 driver=`zzh_mlx90640`、Meta Capture/Streaming
能力、fourcc=`ZMLX` 和 buffer size=3400。每个 Meta payload 校验 magic、version、
header size、buffer size、Chess/Consecutive flags、两个不同 Subpage ID 及时间顺序。

设备编号只用于启动报告，不写入业务逻辑；因此开发板重启后 video 编号变化不会
改变程序选择逻辑。
