# P2.5 MPP编码、OSD与RTSP

## 1. 阶段结论

P2.5在精确提交`b7887575f10351a24c9922c96bc0d0a30de4f0f4`完成并通过
RK3588真机门禁。应用把当前安装姿态下的3840x2160 NV12顺时针旋转270度并
缩放为1080x1920，使用MPP编码High Profile H.264，通过libavformat发布到本机
MediaMTX。P2.4的人员检测、热匹配和告警状态已经进入硬件OSD。

本阶段证明的是单路可解码、可重连的局域网RTSP工程路径，不包含公网安全、鉴权、
音频、录像、H.265或双码流。

## 2. 数据流与所有权

```text
V4L2 4K NV12 MMAP/EXPBUF
          |
          `-> shared_ptr<VisibleFrameLease>
                |-> 容量1推理队列 -> RGA/RKNN -> Fusion -> OverlayState
                `-> 容量1编码队列 -> RGA -> MPP DRM Buffer -> H.264
                                                        |
                                             libavformat RTSP publisher
                                                        |
                                               MediaMTX :8554/p2
```

- 采集回调只创建一个共享租约并投递到两个容量1的`drop-oldest`队列。
- 两个消费者只读同一个V4L2 DMA-BUF；最后一个`shared_ptr`释放时才QBUF。
- 编码线程由RGA把源fd旋转缩放到MPP自有DRM DMA-BUF，不执行4K CPU全帧复制。
- MPP输入、码包和OSD索引各有独立有界Buffer；源fd的RGA handle按6个采集Buffer
  缓存，退出时统一释放。
- 编码慢时只淘汰编码队列旧帧，不反压采集或推理；正式门禁中没有发生淘汰。

该路径减少全帧CPU复制，但RKNN输出后处理、OSD文字/索引生成和H.264码包交给
libavformat仍使用CPU，因此不称端到端零拷贝。

## 3. 编码与发布契约

| 项目 | 固定值 |
|---|---|
| 输入 | 3840x2160 NV12，V4L2 EXPBUF fd |
| 安装方向 | `270cw`，与P2.3/P2.4坐标契约一致 |
| 编码画面 | 1080x1920 NV12，竖向无裁剪2倍缩放 |
| 编码器 | Rockchip MPP AVC，High Profile，30 fps |
| 默认码率/GOP | CBR 6 Mbit/s，60帧 |
| Header | 每个IDR携带SPS/PPS；libavformat同时使用MPP header作extradata |
| 发布 | RTSP over TCP写入`rtsp://127.0.0.1:8554/p2` |
| 服务 | MediaMTX v1.7.0；应用不自行实现RTSP服务器 |
| 时间基 | 编码包按帧序号使用1/30时基，写包前缩放到muxer时基 |

`p2_mpp_stream`是独立编码/OSD/RTSP探针；业务入口仍是
`p2_multimodal_fusion`，通过`--rtsp-url`启用推流，可选`--h264-output`保存
Annex-B证据码流。默认不启用推流，不改变P2.4既有使用方式。

## 4. OSD规则

MPP OSD使用自定义AYUV调色板和最多8个16x16宏块对齐区域。每个像素只保存1字节
调色板索引，未覆盖区域透明。

| 颜色 | 含义 |
|---|---|
| 绿色 | 检出人员，但当前没有热匹配；全局状态为`P2 MONITOR` |
| 黄色 | 人员框已经匹配热ROI，但去抖告警尚未激活 |
| 红色 | 告警已经激活；全局状态为`P2 ALERT` |

框标签为`PERSON <置信度>%`；只有存在对应热匹配时才追加`<温度>C`，避免把背景
温度伪装成人员温度。OSD使用最近一次完成的融合结果，按可见光单调时间戳设置
1秒TTL；超时自动退回无框的绿色`P2 MONITOR`，不无限保留陈旧告警。

检测框原本位于未旋转3840x2160坐标。OSD先执行与编码画面相同的270度坐标变换，
再按0.5比例映射到1080x1920。该变换及匹配/未匹配标签由原生单元测试覆盖。

## 5. 真机门禁

### 5.1 正式60秒

精确提交`b7887575f103`在板端得到：

| 指标 | 结果 |
|---|---:|
| V4L2 DQBUF / 编码帧 / 发布包 | 1796 / 1795 / 1795 |
| 编码队列淘汰 / 发布失败 | 0 / 0 |
| H.264 | High，1080x1920，yuv420p，30/1 fps |
| `ffprobe`完整解码帧 | 1795 |
| RGA / MPP平均耗时 | 10.728 / 5.175 ms |
| MPP源fd导入 | 6次，对应6个采集Buffer |
| OSD覆盖 | 1795/1795帧 |
| 推理 / 热融合 | 1795帧 / 464对 |
| 人员 / 热匹配 / 告警激活 | 928 / 542 / 2次 |
| 采集、推理、温度、融合错误 | 0 |

同一次发布中，FFmpeg客户端在第8秒和第24秒分别连接、解码5秒、主动断开；两次
连接均无解码日志，MediaMTX明确记录两次reader建立和正常teardown。

### 5.2 OSD与重启

- 真实60秒码流按5秒间隔拼图做本地抽检，出现绿色人员框、黄色热匹配框、红色
  告警框、`P2 MONITOR`/`P2 ALERT`切换及匹配温度；含真人的抽帧不提交Git。
- `p2_mpp_stream --demo-overlay`另生成确定性红框和`PERSON 99% 36.5C`证据，验证
  MPP调色板、文字和四边框本身，不作为业务检测结果。
- 仅RTSP、不保存本地H.264的部署模式连续启动5/5通过；每轮234帧编码/发布、
  零队列淘汰、零发布失败，客户端每轮均成功读取。

## 6. 复现

板端先启动MediaMTX，或直接使用仓库门禁脚本：

```sh
scripts/p2_p25_stream_gate.sh /tmp/p2-p25-stream-gate
scripts/p2_p25_restart_gate.sh /tmp/p2-p25-restart-gate
```

正式精选证据位于`evidence/stage5/2026-08-30/`。大体积`.h264`按仓库规则不提交，
只保存SHA-256、`ffprobe`结果、结构化摘要、事件、服务日志和代表性抽帧。

## 7. 边界与下一步

分位、AIQ曝光/增益和持续热目标，并保证默认关、异常/退出写回0；P2.5的编码、
OSD和RTSP不再作为未完成项。
